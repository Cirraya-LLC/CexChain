# Contributing to CexChain

Thank you for your interest in CexChain. Contributions of every size are welcome: bug reports,
fixes, tests, test vectors from independent implementations, documentation, and examples.

CexChain is an alpha: the protocol specification is a draft and may change. Please read this
page before you open a pull request; it explains what a change needs to be merged.

- Security issues: do not open a public issue; see [SECURITY.md](SECURITY.md).
- License: CexChain is licensed under the [Apache License, Version 2.0](LICENSE).
  Contributions are accepted under the same license (see [Licensing](#licensing)).

## Discuss first

Open an issue before you start a large change, so that its design can be agreed before the work
is done. That includes:

- any change to the protocol: statements, ledger rules, evidence, the HTTP API, or the Bo
  language and its packs;
- new commands, new dependencies, and changes to the build or the CI;
- anything that changes a format users store (ledgers, keys, backups, configuration).

Small fixes (a bug with a test, a typo, a clearer message) can go straight to a pull request.

## Principles

These are not negotiable; a change that breaks one will not be merged.

- **Generic by design.** CexChain registers, moves, and proves any thing, under any rules,
  among any parties. What a thing is, its users define. The product itself (protocol, command
  line, help texts, MCP tools, browser verifier) carries no industry concepts: no purchase
  orders, invoices, receivables, or certificates as built-in types or words. Industry stories
  belong in [`examples/`](examples/), built on the generic core. `tests/cli/generic_words.sh`
  checks the product's own texts.
- **Verification code is open source.** Anything that verifies evidence lives in this
  repository, under its license.
- **The protocol is defined by its specification**, not by C++ types: the prose in
  [`spec/README.md`](spec/README.md), the CDDL schema in [`spec/cexchain.cddl`](spec/cexchain.cddl),
  the Bo language in [`spec/bo.md`](spec/bo.md), and the test vectors in
  [`testvectors/`](testvectors/). A protocol change needs spec text, CDDL where the wire format
  changes, and test vectors generated by an implementation independent of CexChain
  (`tools/testvectors/` uses Python's `cryptography` and `cbor2` packages and the OpenSSL
  command-line tool), with C++ tests that check the implementation against them.
- **Determinism.** Code that feeds hashing, signing, or state transitions:
  - uses no floating point;
  - never depends on unordered iteration (hash maps, pointer order);
  - uses a fixed byte order;
  - takes time and randomness as injected inputs, never reading a clock or a random source
    itself.
- **Private data stays off the ledger.** The ledger holds salted commitments, signatures, state
  transitions, grants, and access records, not documents or field values.
- **Machine by default.** A person's action carries proof of presence (a passkey or a hardware
  key); anything without it is attributed to a machine.
- **No home-made cryptography.** Cryptographic primitives come from OpenSSL through the crypto
  interfaces in `core/`; algorithms are pluggable, and national (SM2, SM3), international, and
  post-quantum algorithms coexist.
- **C++ standard by layer.** The core verification library (`core/`) is C++23 with no
  dependencies, so it stays portable to WebAssembly and other compilers. The node and the Bo
  compiler may use C++26.

## Definition of done

A pull request is ready to merge when:

- **It builds with no warnings** with GCC 16 and with Clang (`-Werror` is on in the presets).
- **All tests pass** on:
  - GCC (`gcc-debug`);
  - Clang with AddressSanitizer and UndefinedBehaviorSanitizer (`clang-asan`);
  - Clang with ThreadSanitizer (`clang-tsan`) when the change touches threads, the server, the
    node, or clusters;
  - GCC with sanitizers (`gcc-asan`) when the change touches the Bo compiler;
  - the browser tests (`tests/browser/run.sh`) when the change touches the verifier or its page.
- **It is formatted** with `clang-format` and the repository's `.clang-format` (the CI checks
  every `.cpp` and `.hpp` file with clang-format 23).
- **New behaviour has tests**, and fixed bugs have a test that fails without the fix.
- **Every new parser of untrusted input has a fuzz target** in [`fuzz/`](fuzz/), with valid
  seeds in `fuzz/make_seeds.cpp` where that lets mutations reach the checks.
- **The command line controls the product.** Every capability can be operated from the
  `cexchain` command line:
  - commands to create, inspect, list, and revoke it, as the capability allows;
  - `--help` for each command;
  - `--json` output;
  - shell completion (bash and zsh);
  - coverage in `tests/cli/*.sh`.
- **The documentation is updated:** the README for anything a user sees, and the specification
  for anything a verifier or another implementation must know.
- **New source files carry the license header** (in the comment syntax of the file):

  ```
  SPDX-License-Identifier: Apache-2.0
  Copyright 2026 Cirraya
  ```

- **Every commit is signed off** (see [Developer Certificate of Origin](#developer-certificate-of-origin)).

## Building and testing

Requirements:

- GCC 16 (primary) or a recent Clang (tested with Clang 23)
- CMake 3.28+ and Ninja
- OpenSSL 3.5+
- Optional: the p11-kit headers, for keys on tokens (PKCS #11), and SoftHSM to test them
- Optional: Python 3, to check the Bo runtime on the reference interpreter
- Optional: Emscripten and Node.js, for the browser verifier and its tests

```sh
cmake --preset gcc-debug
cmake --build --preset gcc-debug
ctest --preset gcc-debug
```

Other presets: `gcc-release`, `gcc-asan` (the Bo compiler's tests with AddressSanitizer and
UndefinedBehaviorSanitizer), `clang-debug`, `clang-asan`, `clang-tsan`, and `clang-fuzz`
(libFuzzer targets). Builds go to `build/`, which git ignores.

The Bo compiler (`bo/`) needs GCC 16 for C++26 static reflection and contracts; Clang builds
everything else, the compiler's front end included.

The browser verifier:

```sh
tools/wasm/build.sh build/wasm
(cd tests/browser && npm ci && npx playwright install chromium)
tests/browser/run.sh build/gcc-debug/cli/cexchain build/wasm
```

Fuzzing:

```sh
cmake --preset clang-fuzz && cmake --build --preset clang-fuzz
./build/clang-fuzz/fuzz/make_seeds corpus
./build/clang-fuzz/fuzz/protocol_parse_fuzz corpus/protocol_parse_fuzz -max_total_time=300
```

Test vectors: `tools/testvectors/generate.py` regenerates them (`pip install -r
tools/testvectors/requirements.txt`; `--openssl` names an OpenSSL 3.5+ command-line tool).

`tools/ci-local.sh` runs the CI's Linux jobs locally in the CI's container image under Podman
or Docker. On macOS, Homebrew's LLVM is keg-only: add a `CMakeUserPresets.json` (git ignores
it) that inherits a Clang preset and sets `CMAKE_CXX_COMPILER` to Homebrew's `clang++`.

## Pull requests

- Keep each pull request to one change, and each commit to one logical step.
- Write commit messages that say what changed and why: a short summary line, then the reasons
  and anything a reviewer should know.
- Describe in the pull request how you tested the change.
- Changes under `.github/` (workflows and their scripts) get extra review.
- Do not commit build outputs, keys, ledgers, or personal data.

## Developer Certificate of Origin

Every commit in a pull request must carry a `Signed-off-by:` line with the name and email of
its author, certifying the Developer Certificate of Origin 1.1 (below, and at
<https://developercertificate.org/>). Git adds the line for you with `-s`:

```sh
git commit -s -m "Fix the thing"
```

This adds a trailer such as:

```
Signed-off-by: Your Name <you@example.org>
```

The name and email must match the commit's author (`git config user.name` and
`git config user.email`). Use your real name or the name you are known by; anonymous
contributions cannot be accepted. A check on every pull request fails if a commit (merges
aside) lacks a matching sign-off. To fix it, sign off the commits and force-push:

```sh
git commit --amend --no-edit -s          # the last commit
git rebase --signoff origin/main         # every commit on your branch
git push --force-with-lease
```
