Contract Financing

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.

1. Parties
1.1 issuer: bound to a ledger when an instance is created. [R3]
1.2 supplier: bound to a ledger when an instance is created. [R3]
1.3 bank: bound to a ledger when an instance is created. [R3]
1.4 factor: bound to a ledger by the first sell, with the consent of factor. [R3]

2. Each instance
2.1 Each instance is an asset named Receivable.
2.2 amount: money in HKD, given when an instance is created.
2.3 due: a date, given when an instance is created.
2.4 holder: a party; each instance starts with the supplier, and actions may change it. [R2]
2.5 banker: a party; each instance starts with the bank, and actions may change it. [R2]
2.6 pledgee: a party; each instance starts with none, and actions set it. [R20]
2.7 Creating an instance (function issue) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.
2.8 Dates and days are counted at UTC+08:00 all year, with no daylight saving; a month after a day the next month lacks (31 January plus a month) ends on that month's last day. [R25]

3. States
3.1 An instance starts in the state active. [R4]
3.2 Its states are active and pledged. [R5]
3.3 No state is final: some action can start from any state.
3.4 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

4.1 pledge
  4.1.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show pledge): the clauses marked R19 state them, after the contract's own clauses.
  4.1.2 Started by the holder, whose agreement it needs. [R19]
  4.1.3 Its counterparty is the bank.
  4.1.4 It needs the consent of the bank at every call, since the action makes the bank the pledgee. [R31]
  4.1.5 Requirement 1: the bank is not the holder. [R19]
  4.1.6 If the instance is active, it becomes pledged; otherwise the call is refused. [R19]
  4.1.7 It sets the pledgee to the bank. [R19]
  4.1.8 An AI agent may start it within its delegation. [R14]

4.2 transfer
  4.2.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show transfer): the clauses marked R19 state them, after the contract's own clauses.
  4.2.2 Started by the holder, whose agreement it needs. [R19]
  4.2.3 Its counterparty is the bank.
  4.2.4 It needs the consent of the bank at every call, since the action makes the bank the holder. [R31]
  4.2.5 Requirement 1: the bank is not the holder. [R19]
  4.2.6 If the instance is active, it becomes active; otherwise the call is refused. [R19]
  4.2.7 It sets the holder to the bank. [R19]
  4.2.8 An AI agent may start it within its delegation. [R14]

4.3 release
  4.3.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show release): the clauses marked R19 state them, after the contract's own clauses.
  4.3.2 Started by the pledgee, whose agreement it needs. [R19]
  4.3.3 If the instance is pledged, it becomes active; otherwise the call is refused. [R19]
  4.3.4 It sets the pledgee to none. [R19]
  4.3.5 An AI agent may start it within its delegation. [R14]

4.4 enforce
  4.4.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show enforce): the clauses marked R19 state them, after the contract's own clauses.
  4.4.2 Started by the pledgee, whose agreement it needs. [R19]
  4.4.3 If the instance is pledged, it becomes active; otherwise the call is refused. [R19]
  4.4.4 It sets the holder to the pledgee. [R19]
  4.4.5 It sets the pledgee to none. [R19]
  4.4.6 An AI agent may start it within its delegation. [R14]

4.5 sell
  4.5.1 Started by the holder, whose agreement it needs.
  4.5.2 It needs the consent of factor. The first such call names the ledger of factor and binds factor to it; later calls may leave it out or name the same ledger. [R3]
  4.5.3 Requirement 1: factor is not the holder.
  4.5.4 If the instance is active, it becomes active; otherwise the call is refused.
  4.5.5 It sets the holder to factor.
  4.5.6 An AI agent may start it within its delegation. [R14]

4.6 lodge
  4.6.1 Started by the holder, whose agreement it needs.
  4.6.2 Its counterparty is factor.
  4.6.3 It needs the consent of factor at every call, since the action makes factor the pledgee. [R31]
  4.6.4 It needs the consent of whichever party is the pledgee before the call, since the action changes the pledgee. [R8]
  4.6.5 Requirement 1: factor is not the holder.
  4.6.6 If the instance is active, it becomes pledged; otherwise the call is refused.
  4.6.7 It sets the pledgee to factor.
  4.6.8 An AI agent may start it within its delegation. [R14]

5. Rules Bo applied
[R2] A field given a party holds a party: each instance starts with that party, and actions may change it.
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R5] The states of an instance are those its state changes name.
[R8] Changing a field that holds a party takes it from that party, so it needs that party's consent; when that party starts the action, its call is its consent.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R19] A built-in action has the standard terms Bo's standard library gives it (cexchain bo stdlib show ACTION): who starts it, whose consent it needs, the states it starts from and leads to, and what it changes. The contract's own clauses come first and add to them; R8 adds no consent to the standard terms.
[R20] The pledgee and the payee, and a resource's holder, used by an action (the standard terms of a built-in action included) but not declared by the contract, are fields of each instance, holding no party until an action sets them.
[R25] A contract that names no UTC offset counts dates and days at UTC+08:00.
[R31] An action that makes its counterparty (after to) the holder, the pledgee, or the payee, as transfer, pledge, and allocate do, needs the counterparty's consent at every call, even when its role was bound to a ledger when the instance was created or by another action: nobody becomes a holder, a pledgee, or a payee without agreeing.
