Contract ReceivableFinancing

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.

1. Parties
1.1 issuer: bound to a ledger when an instance is created. [R3]
1.2 supplier: bound to a ledger when an instance is created. [R3]
1.3 bank: bound to a ledger by the first pledge, with the consent of the bank. [R3]

2. Each instance
2.1 Each instance is an asset named Receivable.
2.2 amount: money in HKD, given when an instance is created.
2.3 due: a date, given when an instance is created.
2.4 holder: a party; each instance starts with the supplier, and actions may change it. [R2]
2.5 pledgee: a party; each instance starts with none, and actions set it. [R20]
2.6 Creating an instance (function issue) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.
2.7 Dates and days are counted at UTC+08:00 all year, with no daylight saving; a month after a day the next month lacks (31 January plus a month) ends on that month's last day. [R25]

3. States
3.1 An instance starts in the state active. [R4]
3.2 Its states are active and pledged.
3.3 The state pledged is final: no action can start from it, so an instance in it takes no more calls.
3.4 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

4.1 pledge
  4.1.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show pledge): the clauses marked R19 state them, after the contract's own clauses.
  4.1.2 Started by the holder, whose agreement it needs. [R19]
  4.1.3 It needs the consent of the bank. The first such call names the ledger of the bank and binds the bank to it; later calls may leave it out or name the same ledger. [R3]
  4.1.4 Requirement 1: if the amount is over HKD 5,000,000, the holder must prove presence in person, with a passkey or a hardware key. [R6, R13]
  4.1.5 Requirement 2: the bank is not the holder. [R19]
  4.1.6 If the instance is active, it becomes pledged; otherwise the call is refused. [R19]
  4.1.7 It sets the pledgee to the bank. [R19]
  4.1.8 An AI agent may start it within its delegation. [R14]

4.2 transfer
  4.2.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show transfer): the clauses marked R19 state them, after the contract's own clauses.
  4.2.2 Started by the holder, whose agreement it needs. [R19]
  4.2.3 The call gives counterparty (a party). [R21]
  4.2.4 It needs the consent of the counterparty, whose ledger each call names (the argument counterparty). [R21]
  4.2.5 Requirement 1: the counterparty is not the holder. [R19]
  4.2.6 If the instance is active, it becomes active; otherwise the call is refused. [R19]
  4.2.7 It sets the holder to the counterparty. [R19]
  4.2.8 An AI agent may start it within its delegation. [R14]

5. Time rules
5.1 An instance is due on the due date.

5.2 On the due date:
  5.2.1 Duty: the issuer must pay. It sets when an instance is due and overdue; nothing is called. [R9]

6. Rules Bo applied
[R2] A field given a party holds a party: each instance starts with that party, and actions may change it.
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R6] Over N compares N with the action's one amount (its one input of money or a quantity, else the instance's amount); a bare number N is in that amount's unit.
[R9] A time rule whose action names a party states that party's duty: it sets when an instance is due and overdue, and nothing is called.
[R13] In person asks the party that starts the action to prove presence with a passkey or a hardware key.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R19] A built-in action has the standard terms Bo's standard library gives it (cexchain bo stdlib show ACTION): who starts it, whose consent it needs, the states it starts from and leads to, and what it changes. The contract's own clauses come first and add to them; R8 adds no consent to the standard terms.
[R20] The pledgee and the payee, and a resource's holder, used by an action (the standard terms of a built-in action included) but not declared by the contract, are fields of each instance, holding no party until an action sets them.
[R21] An action whose counterparty (after to) is counterparty, a party the contract does not declare, takes its counterparty from each call (the argument counterparty) and needs its consent; so does a built-in action with a counterparty when the contract writes no to.
[R25] A contract that names no UTC offset counts dates and days at UTC+08:00.
