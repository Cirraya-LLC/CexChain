Contract Batches

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.
Besides Bo's core words, the contract uses the commerce vocabulary pack (version 3).

1. Parties
1.1 we: bound to a ledger when an instance is created. [R3]
1.2 customer: bound to a ledger when an instance is created. [R3]

2. Each instance
2.1 Each instance is a thing named Batch.
2.2 codes: a list of at most 3 items, each a text, given when an instance is created.
2.3 sizes: a list of at most 16 items, each a number, given when an instance is created. [R16]
2.4 total: a number, given when an instance is created.
2.5 Creating an instance (function create) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.

3. States
3.1 An instance starts in the state active. [R4]
3.2 No state is final: some action can start from any state.
3.3 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

4.1 load
  4.1.1 Started by us, whose agreement it needs.
  4.1.2 The call gives rows (a list of at most 4 items, each a number); tags (a list of at most 16 items, each a text). [R16]
  4.1.3 Requirement 1: the number of items in rows is more than 0.
  4.1.4 Requirement 2: the sum of rows is less than 100.
  4.1.5 For each n in rows:
    4.1.5.1 Requirement 3: n is more than 0.
    4.1.5.2 It sets total to total + n.
  4.1.6 For each t in tags:
    4.1.6.1 If t is one of ("x", "y"):
      4.1.6.1.1 The call is refused, with the reason "no x or y".
  4.1.7 Requirement 4: it is not so that "bad" is one of tags.
  4.1.8 It sets sizes to rows.
  4.1.9 An AI agent may start it within its delegation. [R14]

4.2 mark
  4.2.1 Started by us, whose agreement it needs.
  4.2.2 The call gives code (a text).
  4.2.3 Requirement 1: code is one of codes.
  4.2.4 It sets codes to ("a", "b").
  4.2.5 For each s in (1, 2, 3):
    4.2.5.1 Requirement 2: s is less than 5.
  4.2.6 An AI agent may start it within its delegation. [R14]

4.3 check
  4.3.1 Started by the customer, whose agreement it needs.
  4.3.2 The call gives size (a number).
  4.3.3 Requirement 1: size is one of sizes.
  4.3.4 Requirement 2: sizes is (1, 2).
  4.3.5 An AI agent may start it within its delegation. [R14]

5. Rules Bo applied
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R16] A list holds at most 16 items, unless at most N says otherwise.
