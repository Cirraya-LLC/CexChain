Contract StandardLibrary

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.
Besides Bo's core words, the contract uses the finance vocabulary pack (version 2) and the services vocabulary pack (version 3).

1. Parties
1.1 we: bound to a ledger when an instance is created. [R3]
1.2 supplier: bound to a ledger when an instance is created. [R3]

2. Each instance
2.1 Each instance is an asset named Asset.
2.2 holder: a party; each instance starts with the supplier, and actions may change it. [R2]
2.3 amount: money in HKD, given when an instance is created.
2.4 tier: a number, given when an instance is created.
2.5 quantity: a number of items, given when an instance is created.
2.6 cooling period: 30 days, the same for every instance.
2.7 pledgee: a party; each instance starts with none, and actions set it. [R20]
2.8 payee: a party; each instance starts with none, and actions set it. [R20]
2.9 paid until: a date; each instance holds no date until an action sets it. [R20]
2.10 billed until: a date; each instance holds no date until an action sets it. [R20]
2.11 Creating an instance (function issue) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.
2.12 Dates and days are counted at UTC+08:00 all year, with no daylight saving; a month after a day the next month lacks (31 January plus a month) ends on that month's last day. [R25]

3. States
3.1 An instance starts in the state active. [R4]
3.2 Its states are active, cancelled, suspended, terminated, pledged, redeemed, disputed, paid, settled, frozen, divided, cooling, and allocated.
3.3 The state cancelled is final: no action can start from it, so an instance in it takes no more calls.
3.4 The state terminated is final: no action can start from it, so an instance in it takes no more calls.
3.5 The state redeemed is final: no action can start from it, so an instance in it takes no more calls.
3.6 The state settled is final: no action can start from it, so an instance in it takes no more calls.
3.7 The state divided is final: no action can start from it, so an instance in it takes no more calls.
3.8 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

5. Rules Bo applied
[R1] A field the vocabulary defines has the vocabulary's type: holder, pledgee, and payee a party, due a date, tier a number, customer location a text, cooling period a duration, recipients a list of parties.
[R2] A field given a party holds a party: each instance starts with that party, and actions may change it.
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R7] A state used as a condition means the instance is in that state.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R15] Parts are a list of amounts in the unit of the instance's amount.
[R19] A built-in action has the standard terms Bo's standard library gives it (cexchain bo stdlib show ACTION): who starts it, whose consent it needs, the states it starts from and leads to, and what it changes. The contract's own clauses come first and add to them; R8 adds no consent to the standard terms.
[R20] The pledgee and the payee, and a resource's holder, used by an action (the standard terms of a built-in action included) but not declared by the contract, are fields of each instance, holding no party until an action sets them; so are a service's paid until and billed until, holding no date until it is subscribed to.
[R21] An action whose counterparty (after to) is counterparty, a party the contract does not declare, takes its counterparty from each call (the argument counterparty) and needs its consent; so does a built-in action with a counterparty when the contract writes no to.
[R22] A bare 0 compared with, added to, or taken from money, a quantity, a rate, or a duration is zero of it.
[R25] A contract that names no UTC offset counts dates and days at UTC+08:00.
[R30] Issue PARTS to RECIPIENTS makes each part an instance of its own, of the same contract, created by the call: its amount is the part and its holder its recipient, and the instance that issued it ends. A part may be split again, at most eight levels down, and its evidence carries the history of every instance it came from (spec section 15).
