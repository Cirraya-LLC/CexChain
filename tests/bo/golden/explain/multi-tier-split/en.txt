Contract MultiTierReceivable

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.
Besides Bo's core words, the contract uses the finance vocabulary pack (version 1).

1. Parties
1.1 issuer: bound to a ledger when an instance is created. [R3]
1.2 supplier: bound to a ledger when an instance is created. [R3]

2. Each instance
2.1 Each instance is an asset named Receivable.
2.2 amount: money in CNY, given when an instance is created.
2.3 due: a date, given when an instance is created.
2.4 tier: a number, given when an instance is created.
2.5 holder: a party; each instance starts with the supplier, and actions may change it. [R2]
2.6 pledgee: a party; each instance starts with none, and actions set it. [R20]
2.7 payee: a party; each instance starts with none, and actions set it. [R20]
2.8 Creating an instance (function issue) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.
2.9 Dates and days are counted at UTC+08:00 all year, with no daylight saving; a month after a day the next month lacks (31 January plus a month) ends on that month's last day. [R25]

3. States
3.1 An instance starts in the state active. [R4]
3.2 Its states are active, divided, pledged, paid, and settled.
3.3 The state divided is final: no action can start from it, so an instance in it takes no more calls.
3.4 The state settled is final: no action can start from it, so an instance in it takes no more calls.
3.5 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

4.1 split
  4.1.1 A built-in action of the finance vocabulary pack, with the standard terms the pack gives it (cexchain bo stdlib show split): the clauses marked R19 state them, after the contract's own clauses.
  4.1.2 Started by the holder, whose agreement it needs. [R19]
  4.1.3 The call gives parts (a list of at most 16 items, each money in CNY); recipients (a list of at most 16 items, each a party). [R1, R15]
  4.1.4 Requirement 1: the tier is less than 5.
  4.1.5 Requirement 2: the number of items in the recipients is the number of items in the parts. [R19]
  4.1.6 Requirement 3: the number of items in the recipients is at most 15 or the holder is one of the recipients. [R19]
  4.1.7 For each part in the parts: [R19]
    4.1.7.1 Requirement 4: part is more than 0. [R19, R22]
  4.1.8 Requirement 5: the sum of the parts is the amount. [R19]
  4.1.9 Requirement 6: the consent of the recipients. [R19]
  4.1.10 If the instance is active, it becomes divided; otherwise the call is refused. [R19]
  4.1.11 Each of the parts becomes an instance of this contract of its own, a part of this instance: its holder is the party in the same place in the recipients, and its amount is the part. It has this instance's other fields as they are now, except those Bo adds (they start with none), and it starts in the state active. This instance then ends: it takes no more calls. [R19, R30]
  4.1.12 On each part, the tier is set to the tier + 1, computed on this instance. [R19, R30]
  4.1.13 A part may itself be split, down to depth 8, the deepest the ledger allows: on a part at depth 8 the call is refused (bo:depth split). [R19, R30]
  4.1.14 Whoever holds or verifies a part sees the history of each instance it came from, up to the call that split it: the other parts of that call, their holders, and their amounts included. [R19, R30]
  4.1.15 An AI agent may start it within its delegation. [R14]

4.2 transfer
  4.2.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show transfer): the clauses marked R19 state them, after the contract's own clauses.
  4.2.2 Started by the holder, whose agreement it needs. [R19]
  4.2.3 The call gives counterparty (a party). [R21]
  4.2.4 It needs the consent of the counterparty, whose ledger each call names (the argument counterparty). [R21]
  4.2.5 Requirement 1: the counterparty is not the holder. [R19]
  4.2.6 If the instance is active, it becomes active; otherwise the call is refused. [R19]
  4.2.7 It sets the holder to the counterparty. [R19]
  4.2.8 An AI agent may start it within its delegation. [R14]

4.3 pledge
  4.3.1 A built-in action of the finance vocabulary pack, with the standard terms the pack gives it (cexchain bo stdlib show pledge): the clauses marked R19 state them, after the contract's own clauses.
  4.3.2 Started by the holder, whose agreement it needs. [R19]
  4.3.3 The call gives counterparty (a party). [R21]
  4.3.4 It needs the consent of the counterparty, whose ledger each call names (the argument counterparty). [R21]
  4.3.5 Requirement 1: if the amount is over CNY 5,000,000, the holder must prove presence in person, with a passkey or a hardware key. [R6, R13]
  4.3.6 Requirement 2: the counterparty is not the holder. [R19]
  4.3.7 If the instance is active, it becomes pledged; otherwise the call is refused. [R19]
  4.3.8 It sets the pledgee to the counterparty. [R19]
  4.3.9 An AI agent may start it within its delegation. [R14]

4.4 release
  4.4.1 A built-in action of the finance vocabulary pack, with the standard terms the pack gives it (cexchain bo stdlib show release): the clauses marked R19 state them, after the contract's own clauses.
  4.4.2 Started by the pledgee, whose agreement it needs. [R19]
  4.4.3 If the instance is pledged, it becomes active; otherwise the call is refused. [R19]
  4.4.4 It sets the pledgee to none. [R19]
  4.4.5 An AI agent may start it within its delegation. [R14]

4.5 pay
  4.5.1 A built-in action of the finance vocabulary pack, with the standard terms the pack gives it (cexchain bo stdlib show pay): the clauses marked R19 state them, after the contract's own clauses.
  4.5.2 Started by the home ledger on its own word: no party's consent is needed. [R19]
  4.5.3 If the instance is active or pledged, it becomes paid; otherwise the call is refused. [R19]
  4.5.4 If the payee is none: [R19]
    4.5.4.1 If the pledgee is none: [R19]
      4.5.4.1.1 It sets the payee to the holder. [R19]
    4.5.4.2 Otherwise: [R19]
      4.5.4.2.1 It sets the payee to the pledgee. [R19]
  4.5.5 An AI agent may start it within its delegation. [R14]

4.6 confirm payment (function confirm_payment)
  4.6.1 A built-in action of the finance vocabulary pack, with the standard terms the pack gives it (cexchain bo stdlib show confirm_payment): the clauses marked R19 state them, after the contract's own clauses.
  4.6.2 Started by the payee, whose agreement it needs. [R19]
  4.6.3 If the instance is paid, it becomes settled; otherwise the call is refused. [R19]
  4.6.4 An AI agent may start it within its delegation. [R14]

5. Time rules
5.1 An instance is due on the due date.

5.2 On the due date:
  5.2.1 Duty: the issuer must pay. It sets when an instance is due and overdue; nothing is called. [R9]

6. Rules Bo applied
[R1] A field the vocabulary defines has the vocabulary's type: holder, pledgee, and payee a party, due a date, tier a number, customer location a text, cooling period a duration, recipients a list of parties.
[R2] A field given a party holds a party: each instance starts with that party, and actions may change it.
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R6] Over N compares N with the action's one amount (its one input of money or a quantity, else the instance's amount); a bare number N is in that amount's unit.
[R9] A time rule whose action names a party states that party's duty: it sets when an instance is due and overdue, and nothing is called.
[R13] In person asks the party that starts the action to prove presence with a passkey or a hardware key.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R15] Parts are a list of amounts in the unit of the instance's amount.
[R19] A built-in action has the standard terms Bo's standard library gives it (cexchain bo stdlib show ACTION): who starts it, whose consent it needs, the states it starts from and leads to, and what it changes. The contract's own clauses come first and add to them; R8 adds no consent to the standard terms.
[R20] The pledgee and the payee, and a resource's holder, used by an action (the standard terms of a built-in action included) but not declared by the contract, are fields of each instance, holding no party until an action sets them.
[R21] An action whose counterparty (after to) is counterparty, a party the contract does not declare, takes its counterparty from each call (the argument counterparty) and needs its consent; so does a built-in action with a counterparty when the contract writes no to.
[R22] A bare 0 compared with, added to, or taken from money, a quantity, a rate, or a duration is zero of it.
[R25] A contract that names no UTC offset counts dates and days at UTC+08:00.
[R30] Issue PARTS to RECIPIENTS makes each part an instance of its own, of the same contract, created by the call: its amount is the part and its holder its recipient, and the instance that issued it ends. A part may be split again, at most eight levels down, and its evidence carries the history of every instance it came from (spec section 15).
