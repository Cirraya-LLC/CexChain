Contract WarehouseReceipt

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.

1. Parties
1.1 we: bound to a ledger when an instance is created. [R3]
1.2 depositor: bound to a ledger when an instance is created. [R3]
1.3 bank: bound to a ledger by the first pledge, with the consent of the bank. [R3]

2. Each instance
2.1 Each instance is an asset named Receipt.
2.2 quantity: a weight (kg, tonnes), given when an instance is created.
2.3 holder: a party; each instance starts with depositor, and actions may change it. [R2]
2.4 pledgee: a party; each instance starts with none, and actions set it. [R20]
2.5 Creating an instance (function issue) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.

3. States
3.1 An instance starts in the state active. [R4]
3.2 Its states are active, pledged, redeemed, frozen, and cancelled. [R5]
3.3 The state redeemed is final: no action can start from it, so an instance in it takes no more calls.
3.4 The state cancelled is final: no action can start from it, so an instance in it takes no more calls.
3.5 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

4.1 transfer
  4.1.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show transfer): the clauses marked R19 state them, after the contract's own clauses.
  4.1.2 Started by the holder, whose agreement it needs. [R19]
  4.1.3 The call gives counterparty (a party). [R21]
  4.1.4 It needs the consent of the counterparty, whose ledger each call names (the argument counterparty). [R21]
  4.1.5 Requirement 1: the counterparty is not the holder. [R19]
  4.1.6 If the instance is active, it becomes active; otherwise the call is refused. [R19]
  4.1.7 It sets the holder to the counterparty. [R19]
  4.1.8 An AI agent may start it within its delegation. [R14]

4.2 pledge
  4.2.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show pledge): the clauses marked R19 state them, after the contract's own clauses.
  4.2.2 Started by the holder, whose agreement it needs. [R19]
  4.2.3 It needs the consent of the bank. The first such call names the ledger of the bank and binds the bank to it; later calls may leave it out or name the same ledger. [R3]
  4.2.4 Requirement 1: the holder must prove presence in person, with a passkey or a hardware key. [R13]
  4.2.5 Requirement 2: the bank is not the holder. [R19]
  4.2.6 If the instance is active, it becomes pledged; otherwise the call is refused. [R19]
  4.2.7 It sets the pledgee to the bank. [R19]
  4.2.8 An AI agent may start it within its delegation. [R14]

4.3 release
  4.3.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show release): the clauses marked R19 state them, after the contract's own clauses.
  4.3.2 Started by the pledgee, whose agreement it needs. [R19]
  4.3.3 If the instance is pledged, it becomes active; otherwise the call is refused. [R19]
  4.3.4 It sets the pledgee to none. [R19]
  4.3.5 An AI agent may only propose it: its call is kept as a proposal, which takes effect only when a person who proves presence approves it; every requirement is checked then.

4.4 redeem
  4.4.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show redeem): the clauses marked R19 state them, after the contract's own clauses.
  4.4.2 Started by the holder, whose agreement it needs. [R19]
  4.4.3 The call gives portion (a weight (kg, tonnes)). [R19]
  4.4.4 Requirement 1: the instance is active or pledged. [R7, R19]
  4.4.5 If the instance is pledged: [R7, R19]
    4.4.5.1 Requirement 2: the consent of the pledgee. [R19]
  4.4.6 Requirement 3: the portion is more than 0. [R19, R22]
  4.4.7 Requirement 4: the portion is at most the quantity. [R19]
  4.4.8 It sets the quantity to the quantity − the portion. [R19]
  4.4.9 If the quantity is 0: [R19, R22]
    4.4.9.1 It sets the pledgee to none. [R19]
    4.4.9.2 The instance becomes redeemed. [R19]
  4.4.10 An AI agent may start it within its delegation. [R14]

4.5 freeze
  4.5.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show freeze): the clauses marked R19 state them, after the contract's own clauses.
  4.5.2 Started by the home ledger on its own word: no party's consent is needed. [R19]
  4.5.3 If the instance is active or pledged, it becomes frozen; otherwise the call is refused. [R19]
  4.5.4 An AI agent may start it within its delegation. [R14]

4.6 unfreeze
  4.6.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show unfreeze): the clauses marked R19 state them, after the contract's own clauses.
  4.6.2 Started by the home ledger on its own word: no party's consent is needed. [R19]
  4.6.3 If the instance is frozen, it returns to the state it was in before it became frozen; otherwise the call is refused. [R19]
  4.6.4 An AI agent may start it within its delegation. [R14]

4.7 cancel
  4.7.1 A built-in action of Bo, with the standard terms of Bo's standard library (cexchain bo stdlib show cancel): the clauses marked R19 state them, after the contract's own clauses.
  4.7.2 Started by the holder, whose agreement it needs. [R19]
  4.7.3 If the instance is active, it becomes cancelled; otherwise the call is refused. [R19]
  4.7.4 An AI agent may start it within its delegation. [R14]

4.8 lodge
  4.8.1 Started by the holder, whose agreement it needs.
  4.8.2 The call gives counterparty (a party). [R21]
  4.8.3 It needs the consent of the counterparty, whose ledger each call names (the argument counterparty). [R21]
  4.8.4 It needs the consent of whichever party is the pledgee before the call, since the action changes the pledgee. [R8]
  4.8.5 Requirement 1: the counterparty is not the holder.
  4.8.6 If the instance is active, it becomes pledged; otherwise the call is refused.
  4.8.7 It sets the pledgee to the counterparty.
  4.8.8 An AI agent may start it within its delegation. [R14]

4.9 approve
  4.9.1 approve (function approve): a person who proves presence approves a proposal an AI agent made, naming its function and arguments. The proposal then runs as its action does, started by that action's starter, with every requirement checked. An instance keeps at most 16 proposals. [R14]

5. Rules Bo applied
[R2] A field given a party holds a party: each instance starts with that party, and actions may change it.
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R5] The states of an instance are those its state changes name.
[R7] A state used as a condition means the instance is in that state.
[R8] Changing a field that holds a party takes it from that party, so it needs that party's consent; when that party starts the action, its call is its consent.
[R13] In person asks the party that starts the action to prove presence with a passkey or a hardware key.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R19] A built-in action has the standard terms Bo's standard library gives it (cexchain bo stdlib show ACTION): who starts it, whose consent it needs, the states it starts from and leads to, and what it changes. The contract's own clauses come first and add to them; R8 adds no consent to the standard terms.
[R20] The pledgee and the payee, used by an action (the standard terms of a built-in action included) but not declared by the contract, are fields of each instance, holding no party until an action sets them.
[R21] An action whose counterparty (after to) is counterparty, a party the contract does not declare, takes its counterparty from each call (the argument counterparty) and needs its consent; so does a built-in action with a counterparty when the contract writes no to.
[R22] A bare 0 compared with, added to, or taken from money, a quantity, a rate, or a duration is zero of it.
