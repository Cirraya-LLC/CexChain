Contract Agreement

Bo wrote this text from the contract's source (Bo edition 1). A clause marked with a rule, such as [R3], states what Bo inferred by that rule instead of reading it in the source; the last section explains each rule.
Besides Bo's core words, the contract uses the commerce vocabulary pack (version 3).

1. Parties
1.1 we: bound to a ledger when an instance is created. [R3]
1.2 customer: bound to a ledger when an instance is created. [R3]

2. Each instance
2.1 Each instance is a thing named Terms.
2.2 terms: a text, given when an instance is created.
2.3 amount: money in HKD, given when an instance is created.
2.4 starts: a date, given when an instance is created.
2.5 Creating an instance (function create) names the ledgers of the parties bound at creation and sets the fields given at creation. It needs no party's consent: the parties agree through the actions below.
2.6 Dates and days are counted at UTC+08:00 all year, with no daylight saving; a month after a day the next month lacks (31 January plus a month) ends on that month's last day. [R25]

3. States
3.1 An instance starts in the state proposed. [R4]
3.2 Its states are proposed, signed, effective, and closed. [R5]
3.3 The state closed is final: no action can start from it, so an instance in it takes no more calls.
3.4 Each change of state, the first state included, is recorded as an event.

4. Actions
A call that does not meet one of an action's requirements is refused, and the instance does not change. A missing consent is not a refusal: the call waits for it.

4.1 amend
  4.1.1 Started by us, whose agreement it needs.
  4.1.2 The call gives new_amount (money in HKD); new_start (a date).
  4.1.3 Requirement 1: the instance is proposed. [R7]
  4.1.4 Requirement 2: the consent of the customer.
  4.1.5 Requirement 3: new_amount is more than HKD 0.
  4.1.6 If new_amount is more than the amount × 150%: [R17]
    4.1.6.1 The call is refused, with the reason "an amendment may raise the amount by half at most".
  4.1.7 Otherwise:
    4.1.7.1 It sets the amount to new_amount.
  4.1.8 It sets starts to new_start.
  4.1.9 An AI agent may start it within its delegation. [R14]

4.2 sign
  4.2.1 Started by the customer, whose agreement it needs.
  4.2.2 Requirement 1: if the amount is over HKD 1,000,000, the customer must prove presence in person, with a passkey or a hardware key. [R6, R13]
  4.2.3 Requirement 2: the time of the call is before starts.
  4.2.4 If the instance is proposed, it becomes signed; otherwise the call is refused.
  4.2.5 An AI agent may start it within its delegation. [R14]

4.3 countersign
  4.3.1 Started by us, whose agreement it needs.
  4.3.2 If the instance is signed, it becomes effective; otherwise the call is refused.
  4.3.3 An AI agent may start it within its delegation. [R14]

4.4 close
  4.4.1 Started by us, whose agreement it needs.
  4.4.2 Requirement 1: the consent of the customer.
  4.4.3 If the instance is effective, it becomes closed; otherwise the call is refused.
  4.4.4 An AI agent may start it within its delegation. [R14]

5. Rules Bo applied
[R3] A role the contract first names as an action's counterparty (after to) is bound to a ledger by that action, with its consent; every other role is bound to a ledger when an instance is created.
[R4] An instance starts in the one state that no state change leads to; if there is none, in the state active.
[R5] The states of an instance are those its state changes name.
[R6] Over N compares N with the action's one amount (its one input of money or a quantity, else the instance's amount); a bare number N is in that amount's unit.
[R7] A state used as a condition means the instance is in that state.
[R13] In person asks the party that starts the action to prove presence with a passkey or a hardware key.
[R14] An AI agent may start an action within its delegation, unless the action says AI agent can propose; then the agent only proposes, and a person approves.
[R17] A product or quotient of money, quantities, or rates is rounded to the smallest unit, half up (away from zero).
[R25] A contract that names no UTC offset counts dates and days at UTC+08:00.
